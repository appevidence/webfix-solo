# Установка, развёртывание, настройка и запуск `webfix-solo`

> Полное руководство для двух аудиторий и двух окружений.
>
> **Аудитории**
> - 🛠️ **Технический персонал** (devops / инженер / администратор) — лаконичные команды, объяснение что и зачем.
> - 👤 **Обычный единичный пользователь — юрист** — пошагово, «нажал сюда → перешёл туда → скачал то».
>
> **Окружения**
> - **A. GitHub Codespaces** — браузерная среда разработки от GitHub, ничего не нужно ставить на свой компьютер.
> - **B. Ubuntu 24.04 локально** — установка прямо на ваш ноутбук/ПК с Ubuntu 24.04 LTS.

## ⚠️ Важный дисклеймер о статусе проекта

`webfix-solo` находится в стадии **pre-alpha**. Это значит:

- ✅ Установка, тесты, запуск `webfix --help` и `webfix --version` — **полностью работают**.
- ⏳ Команды `webfix init`, `webfix capture`, `webfix verify`, `webfix export`, `webfix report`, `webfix audit …` — на момент написания этого руководства **возвращают сообщение "not yet ported from Repo A"** и завершаются с кодом 2. Это **запланированное** поведение: каркас CLI готов, а реализация портируется из родительского репозитория [`appevidence/evidence-capture-app`](https://github.com/appevidence/evidence-capture-app). Прогресс порта — в [`docs/Current-State.md`](Current-State.md).

Иначе говоря: руководство ниже **корректно описывает то, что уже работает сегодня**, и **готово к тому моменту, когда команды захвата заработают** — никаких новых шагов установки тогда не понадобится.

Юридический статус собранных бандлов — см. дисклеймер в [`README.md`](../README.md#what-it-is-not--обязательный-дисклеймер--mandatory-disclaimer).

# A. GitHub Codespaces

GitHub Codespaces — это полноценная среда разработки в браузере. Ничего на свой компьютер устанавливать не нужно: всё крутится на серверах GitHub, вы работаете через VS Code в браузере (или в десктоп-VS Code, если хотите).

В репозитории есть готовая конфигурация [`.devcontainer/devcontainer.json`](../.devcontainer/devcontainer.json), поэтому Codespace поднимется «из коробки»: Python 3.12, все зависимости проекта, браузер Chromium для Playwright и расширения VS Code устанавливаются автоматически.

## A.1. Для технического персонала (Codespaces)

### Что произойдёт автоматически

При создании Codespace из этого репозитория:

1. Запустится контейнер на базе образа `mcr.microsoft.com/devcontainers/python:1-3.12-bookworm`.
2. Скрипт [`.devcontainer/post-create.sh`](../.devcontainer/post-create.sh) выполнит:
   - `pip install --upgrade pip`
   - `pip install -e ".[dev,ots]"` — проект в editable-режиме плюс dev-инструменты (`pytest`, `ruff`, `mypy`, `pre-commit`) и опциональный extra `ots` (OpenTimestamps).
   - `python -m playwright install --with-deps chromium` — браузер Chromium и его системные библиотеки (`libnss3`, `libatk1.0-0`, и т.д.).
   - `webfix --version` и `pytest -q` как smoke-тест.
3. Переменные окружения по умолчанию:
   - `WEBFIX_DATA_DIR=${containerWorkspaceFolder}/.webfix-data` — все ключи / БД / аудит-лог / бандлы будут лежать внутри workspace, а не в `~/.local/share`. Удобно: видно в файловом дереве VS Code, не теряется при пересоздании Codespace (если вы не делаете `Rebuild Container`).
   - `PLAYWRIGHT_BROWSERS_PATH=${containerWorkspaceFolder}/.ms-playwright` — кеш браузеров тоже внутри workspace.
   - Обе папки добавлены в [`.gitignore`](../.gitignore), в Git они не попадут.

### Создание Codespace

1. Откройте репозиторий: `https://github.com/appevidence/webfix-solo`.
2. Кнопка **Code** (зелёная) → вкладка **Codespaces** → **Create codespace on `main`**.
3. Подождите 2–4 минуты (сборка контейнера + post-create).

### Проверка работоспособности (минимальный smoke-тест)

```bash
webfix --version          # webfix 0.0.1
webfix --help             # увидеть список команд
pytest -q                 # 63 теста, все должны быть зелёные
ruff check .              # линт
ruff format --check .     # формат
```

Если хотите вручную убедиться, что Chromium стартует:

```bash
python -c "from playwright.sync_api import sync_playwright; \
  p = sync_playwright().start(); \
  b = p.chromium.launch(); \
  print(b.new_page().goto('https://example.com').status); \
  b.close(); p.stop()"
```

### Работа с проектом

```bash
# Линт + автоформат
ruff check . --fix
ruff format .

# Тесты с покрытием
pytest --cov=webfix --cov=app

# Полный набор pre-commit (если настроен hook)
pre-commit run --all-files
```

### Типичные проблемы и решения

| Симптом | Что делать |
|---|---|
| `playwright install` падает с правами / apt-get | post-create уже использует `--with-deps`. Если контейнер пересоздавали без sudo — повторите вручную: `sudo python -m playwright install-deps && python -m playwright install chromium`. |
| `webfix capture …` пишет «is not yet ported» | **Это не баг.** Команда ещё не подключена к модулям `app/*`. См. дисклеймер в начале документа. |
| Codespace зависает при старте | Удалите Codespace через `https://github.com/codespaces` и создайте заново. |

### Остановка / удаление Codespace

- **Stop** — `https://github.com/codespaces` → три точки рядом с вашим Codespace → **Stop codespace**. Файлы сохраняются, биллинг за CPU прекращается, остаётся только биллинг за хранилище.
- **Delete** — там же → **Delete**. Удаляет всё, в т.ч. `.webfix-data/`. Если внутри лежат сгенерированные ключи или бандлы — **сначала скачайте их** через `Download…` в VS Code или через `gh codespace cp`.

## A.2. Для юриста — пошагово (Codespaces)

> 💡 Зачем юристу Codespaces? — Не нужно устанавливать ничего на свой компьютер: ни Python, ни браузер, ни командную строку. Всё открывается в обычном веб-браузере (Chrome, Firefox, Edge — любой современный).
>
> 💡 Что нужно заранее? — Учётная запись на GitHub. Бесплатной (Free) хватает: каждый месяц даётся бесплатный лимит часов Codespaces, для эпизодической работы — с запасом.

### Шаг 1. Создать аккаунт на GitHub (если ещё нет)

1. Откройте в браузере: **https://github.com/signup**
2. Введите свой email → нажмите **Continue**.
3. Придумайте пароль (минимум 15 символов, или 8 символов + цифра + строчная буква) → **Continue**.
4. Придумайте имя пользователя (логин) → **Continue**.
5. Подтвердите email письмом, которое придёт от GitHub.

### Шаг 2. Открыть репозиторий

1. В адресной строке браузера введите: **`https://github.com/appevidence/webfix-solo`** → нажмите **Enter**.
2. Откроется страница проекта. В правом верхнем углу страницы должно быть видно ваш логин (значит, вы залогинены). Если не залогинены — нажмите **Sign in** в правом верхнем углу.

### Шаг 3. Запустить Codespace

1. На странице репозитория найдите **зелёную кнопку `<> Code`** (примерно по центру, над списком файлов).
2. Нажмите на неё. Появится небольшое окошко с двумя вкладками: **Local** и **Codespaces**.
3. Перейдите на вкладку **Codespaces**.
4. Нажмите на зелёную кнопку **`Create codespace on main`**.
5. Откроется новая вкладка браузера. Появится тёмный экран с надписью «Setting up your codespace…». Подождите **2–4 минуты** (только при первом запуске; в следующие разы быстрее).
6. Когда сборка закончится, вы увидите **редактор VS Code прямо в браузере**. Слева — дерево файлов проекта. Снизу — чёрное окно «Terminal» (командная строка).

> Если терминала не видно: меню сверху → **Terminal** → **New Terminal** (или клавиши `` Ctrl+` ``).

### Шаг 4. Убедиться, что всё установилось

В терминале (чёрное окно снизу) напечатайте:

```
webfix --version
```

…и нажмите **Enter**. Должна появиться строчка вида:

```
webfix 0.0.1
```

Затем напечатайте:

```
webfix --help
```

…и снова **Enter**. Появится список команд (`init`, `capture`, `verify`, `export`, `report`, `audit`).

✅ **Всё установилось правильно.**

### Шаг 5. Что делать дальше

На сегодняшний день (pre-alpha) команды захвата веб-страницы (`webfix capture …`) ещё не подключены — при их запуске вы увидите сообщение «is not yet ported from Repo A». Это нормально: разработчики дописывают функционал.

Когда команды заработают, рабочий день будет выглядеть так:

1. Открыть Codespace (шаг 3 выше — вторая и далее загрузки занимают **15–30 секунд**, а не 2–4 минуты).
2. В терминале один раз создать локальное хранилище (вас попросят придумать пароль для приватного ключа — **запомните его**, лучше запишите в менеджер паролей):
   ```
   webfix init
   ```
3. Зафиксировать веб-страницу:
   ```
   webfix capture https://example.com
   ```
   В папке проекта (слева в дереве файлов) появится `.zip`-файл — это и есть «бандл доказательств».
4. Скачать бандл к себе на компьютер: правой кнопкой по `.zip`-файлу в дереве слева → **Download…** → выбрать папку на компьютере → **Сохранить**.
5. Проверить целостность бандла перед тем, как куда-то его прикладывать:
   ```
   webfix verify ./bundle.zip
   ```
6. Сделать «человекочитаемый» PDF-отчёт по бандлу:
   ```
   webfix report ./bundle.zip --pdf otchet.pdf
   ```
   Полученный `otchet.pdf` тоже скачать через **Download…**.

### Шаг 6. Закончить работу

- Чтобы **временно закрыть** (файлы сохранятся, в следующий раз продолжите): просто закройте вкладку браузера. GitHub автоматически остановит Codespace через ~30 минут бездействия.
- Чтобы **точно остановить сейчас**: откройте **https://github.com/codespaces** → найдите ваш Codespace в списке → нажмите **«…»** справа → **Stop codespace**.
- Чтобы **полностью удалить** (со всеми файлами внутри): там же → **«…»** → **Delete**. ⚠️ Перед удалением скачайте все нужные `.zip`-бандлы и PDF на свой компьютер.

# B. Ubuntu 24.04 локально

## B.1. Для технического персонала (Ubuntu 24.04)

### Системные требования

- Ubuntu 24.04 LTS (Noble Numbat). На 22.04 / Debian 12 тоже работает, но шаги ниже даны для 24.04.
- Минимум 2 ГБ свободной RAM (Chromium + Python).
- ~600 МБ места на диске (в основном Chromium для Playwright).
- Доступ в интернет для `pip install` и `playwright install`.
- Привилегии `sudo` (нужны только один раз — для `playwright install --with-deps`).

### Установка системных пакетов

```bash
sudo apt update
sudo apt install -y python3.12 python3.12-venv python3-pip git
# Опционально, но рекомендуется — для удобной работы:
sudo apt install -y python3.12-dev build-essential
```

> Python 3.12 идёт в Ubuntu 24.04 «из коробки», отдельных PPA добавлять не нужно.

### Получение исходников

```bash
git clone https://github.com/appevidence/webfix-solo.git
cd webfix-solo
```

### Виртуальное окружение и установка

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e ".[dev,ots]"
```

Опциональные extras:

| Extra | Команда | Что даёт |
|---|---|---|
| `ots` | `pip install -e ".[ots]"` | OpenTimestamps-доказательства (флаг `--with-ots`) |
| `wayback` | `pip install -e ".[wayback]"` | Submission в Wayback Machine (флаг `--with-wayback`) |
| `eth` | `pip install -e ".[eth]"` | Якорение в Ethereum (флаг `--with-eth`); требует приватный ключ и газ |
| `dev` | `pip install -e ".[dev]"` | `pytest`, `ruff`, `mypy`, `pre-commit` |

Можно комбинировать: `pip install -e ".[dev,ots,wayback]"`.

### Установка браузера для Playwright

```bash
sudo python -m playwright install-deps chromium   # apt-пакеты, нужны один раз
python -m playwright install chromium             # сам бинарник Chromium
```

Эквивалент в одну команду (требует sudo):

```bash
sudo python -m playwright install --with-deps chromium
```

### Smoke-тест

```bash
webfix --version           # webfix 0.0.1
webfix --help
pytest -q                  # должно быть 63 passed
ruff check . && ruff format --check .
```

### Конфигурация — переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `WEBFIX_DATA_DIR` | Корневая папка данных (`keys/`, `db.sqlite`, `audit.log`, `bundles/`). | `$XDG_DATA_HOME/webfix-solo`, иначе `~/.local/share/webfix-solo` |
| `XDG_DATA_HOME` | Стандарт XDG; используется, если `WEBFIX_DATA_DIR` не задан. | не задана → `~/.local/share` |
| `PLAYWRIGHT_BROWSERS_PATH` | Куда Playwright кладёт браузеры. | `~/.cache/ms-playwright` |

Чтобы переменная действовала постоянно — добавьте в `~/.bashrc` (или `~/.zshrc`):

```bash
echo 'export WEBFIX_DATA_DIR="$HOME/webfix-data"' >> ~/.bashrc
source ~/.bashrc
```

### Развёртывание / системная установка

Для одиночного пользователя «развёртывание» = виртуальное окружение в его `$HOME`. Никакого systemd-юнита, никаких портов, никакого Docker — это и есть смысл Repo C.

Если очень хочется сделать `webfix` доступным глобально (без активации `venv`), добавьте симлинк:

```bash
sudo ln -s "$PWD/.venv/bin/webfix" /usr/local/bin/webfix
```

…но это не рекомендуется: при обновлении проекта через `git pull` editable-установка продолжит работать, а вот при пересоздании venv симлинк сломается.

### Обновление

```bash
cd ~/webfix-solo            # или где у вас лежит репозиторий
git pull
source .venv/bin/activate
pip install -e ".[dev,ots]"  # подхватит новые зависимости из pyproject.toml
python -m playwright install chromium  # на случай, если в проекте обновили версию playwright
pytest -q                    # убедиться, что ничего не сломалось
```

### Удаление

```bash
deactivate 2>/dev/null || true
rm -rf ~/webfix-solo                  # исходники + venv
rm -rf ~/.local/share/webfix-solo     # данные (ключи, БД, бандлы) — ВНИМАТЕЛЬНО
rm -rf ~/.cache/ms-playwright          # браузеры
```

### Типичные проблемы

| Симптом | Решение |
|---|---|
| `webfix: command not found` | Не активирован venv. Выполните `source ~/webfix-solo/.venv/bin/activate`. |
| `playwright._impl._errors.Error: Executable doesn't exist at …` | Не выполнен `python -m playwright install chromium`. |
| `Host system is missing dependencies to run browsers` | Не установлены apt-зависимости. `sudo python -m playwright install-deps chromium`. |
| `… is not yet ported from Repo A` | Известное поведение pre-alpha (см. дисклеймер вверху). |
| `pip install` не находит `python3.12` | На «голой» Ubuntu 24.04: `sudo apt install python3.12 python3.12-venv`. |

## B.2. Для юриста — пошагово (Ubuntu 24.04)

> 💡 Эта часть рассчитана на пользователя, который **уже работает на Ubuntu 24.04** и умеет запускать «Терминал», но не более того. Никаких знаний программирования не требуется — все команды нужно просто скопировать и вставить.
>
> 💡 Если у вас Windows или macOS, проще пользоваться **GitHub Codespaces** (раздел A.2 выше) — там не нужно ничего устанавливать.

### Шаг 1. Открыть «Терминал»

1. Нажмите клавишу `Super` (это клавиша с логотипом Windows на клавиатуре) — откроется поиск приложений.
2. Напечатайте слово **`Терминал`** (или `Terminal`).
3. Кликните по иконке **Терминал**. Откроется чёрное (или фиолетовое) окно с мигающим курсором.

> Альтернатива: горячие клавиши `Ctrl + Alt + T`.

### Шаг 2. Установить системные программы (один раз)

Скопируйте всю строчку ниже целиком, **вставьте в Терминал** (правая кнопка мыши → **Paste**, или `Ctrl+Shift+V`) и нажмите **Enter**:

```
sudo apt update && sudo apt install -y python3.12 python3.12-venv python3-pip git
```

Терминал спросит **пароль вашего пользователя** (тот, которым вы входите в систему). Напечатайте его и нажмите **Enter**. ⚠️ Символы пароля не отображаются — это нормально. Дальше система может спросить «Continue? [Y/n]» — нажмите **`Y`** и **Enter**.

Подождите 1–3 минуты, пока установка закончится (Терминал снова покажет ваш привычный приглашающий значок `$`).

### Шаг 3. Скачать программу `webfix-solo`

Скопируйте и вставьте в Терминал по очереди (по одной строке, после каждой — **Enter**):

```
cd ~
```

```
git clone https://github.com/appevidence/webfix-solo.git
```

```
cd webfix-solo
```

После третьей команды вы окажетесь «внутри» папки с программой. Подсказка слева станет такой: `…/webfix-solo$`.

### Шаг 4. Подготовить «песочницу» Python и установить программу (один раз)

Скопируйте каждую строчку отдельно, после каждой — **Enter**:

```
python3.12 -m venv .venv
```

```
source .venv/bin/activate
```

После второй команды слева в подсказке появится приставка `(.venv)` — это означает, что «песочница» активирована.

```
pip install --upgrade pip
```

```
pip install -e ".[dev,ots]"
```

Последняя команда долгая — **2–5 минут**. Будут бежать строчки про `Downloading…` и `Installing collected packages…`. Когда снова появится приглашение `$`, скопируйте и выполните:

```
sudo python -m playwright install --with-deps chromium
```

Опять может попросить пароль — введите. Эта команда тоже долгая (3–6 минут): она скачивает встроенный браузер Chromium.

### Шаг 5. Проверить, что всё работает

Скопируйте и выполните:

```
webfix --version
```

Должно появиться:

```
webfix 0.0.1
```

И:

```
webfix --help
```

Появится таблица с командами (`init`, `capture`, `verify`, …).

✅ **Установка завершена.**

### Шаг 6. Как заходить в программу в следующие разы

Когда вы закроете Терминал и потом захотите снова работать с `webfix-solo`, **повторно устанавливать ничего не нужно**. Каждый раз нужно только две команды:

1. Открыть **Терминал** (`Ctrl+Alt+T`).
2. Скопировать и выполнить:
   ```
   cd ~/webfix-solo && source .venv/bin/activate
   ```
3. Дальше работайте обычными командами `webfix …`.

### Шаг 7. Что делать дальше

> ⚠️ На сегодняшний день программа в стадии **pre-alpha**. Команды `webfix init`, `webfix capture …`, `webfix verify …` показывают сообщение «is not yet ported from Repo A» и не выполняют действие. Это **запланировано**: разработчики дописывают эти команды, обновится через `git pull` (см. ниже).

Когда команды заработают, ваш типовой рабочий день будет выглядеть так:

1. **Один раз**, чтобы создать локальное хранилище ключей и базы данных:
   ```
   webfix init
   ```
   Программа попросит **придумать пароль для секретного ключа**. ⚠️ **Этот пароль — единственный способ подписать ваши будущие бандлы. Запишите его в менеджер паролей. При утере восстановить нельзя.**

2. **Чтобы зафиксировать веб-страницу как доказательство** — пример:
   ```
   webfix capture https://example.com
   ```
   В текущей папке появится файл вида `bundle-2026….zip`. Это и есть «доказательственный пакет»: HTML, скриншот, PDF страницы, HAR (журнал сетевых запросов), хеши SHA-256 всех файлов и ваша Ed25519-подпись.

3. **Чтобы сгенерировать читаемый PDF-отчёт** по бандлу:
   ```
   webfix report ./bundle-….zip --pdf otchet.pdf
   ```
   Файл `otchet.pdf` появится рядом — его можно открывать обычным просмотрщиком PDF и прикладывать к процессуальным документам.

4. **Чтобы убедиться, что бандл не был подменён** (полезно при получении бандла со стороны или перед подачей в суд):
   ```
   webfix verify ./bundle-….zip
   ```

5. **Где лежат файлы.** По умолчанию все ключи / база / журнал лежат в скрытой папке `~/.local/share/webfix-solo/`. Чтобы её посмотреть в файловом менеджере «Файлы» (Nautilus): меню **Вид** → **Показывать скрытые файлы** (или `Ctrl+H`). Готовые бандлы (`.zip`) — там же в подпапке `bundles/`.

### Шаг 8. Обновление до новой версии

Раз в месяц (или когда захочется) — открыть Терминал и выполнить:

```
cd ~/webfix-solo && source .venv/bin/activate
git pull
pip install -e ".[dev,ots]"
python -m playwright install chromium
```

Это безопасно: ваши ключи и бандлы лежат в **отдельной** папке `~/.local/share/webfix-solo/` и при обновлении не трогаются.

### Шаг 9. Что делать, если что-то пошло не так

| Что вижу в Терминале | Что сделать |
|---|---|
| `webfix: command not found` | Забыли активировать «песочницу». Выполнить `cd ~/webfix-solo && source .venv/bin/activate`. |
| `is not yet ported from Repo A` | Это не ошибка — функция ещё не реализована (см. дисклеймер). Подождите следующего обновления и выполните Шаг 8. |
| `Host system is missing dependencies` | Выполнить `sudo python -m playwright install-deps chromium`. |
| `Permission denied` при `sudo …` | Перепроверьте, что пароль введён правильно (символы не отображаются). |
| Пропал значок `(.venv)` слева | Снова выполнить `source ~/webfix-solo/.venv/bin/activate`. |
